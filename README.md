# A股短线推荐、回测与模拟盘

给大约 2 万元本金的 A 股个人投资者用的研究工具。每个交易日收盘后，它更新免费行情，给出下一交易日可以考虑的候选股票，并用同一套规则做历史回测和模拟盘记账。

**v1 不会连接券商，也不会发出真实委托。** 下单口子只实现了模拟盘。以后如果要接 miniQMT，只需要新写一个券商适配器，不用改策略和记账规则。

这不是投资建议。短线交易可能把本金亏掉，过去的回测数字不能当成未来收益。

## 它做什么

1. **收盘后选股。** 一条命令更新数据，写出 Markdown 和 CSV。每只候选包含策略理由、建议买入价区间、止盈价、止损价、最长持有交易日，以及按 2 万元和 100 股一手算出来的股数。
2. **五条短线策略。** 参数写在代码里，走步检验时只用一小格参数，避免把网格搜得很细。
3. **回测。** 按 A 股规则撮合：T+1、涨停买不进、跌停卖不出、佣金最低 5 元、卖出印花税、过户费、滑点、整手。输出总收益、年化、胜率、平均盈亏、最大回撤、成交笔数和权益曲线。另外做走步样本外，用来看参数是不是只在历史里好看。
4. **模拟盘。** 把当日候选记成“下一交易日开盘”委托，之后用日线结算，累计盈亏。
5. **本地看盘页。** 一条命令打开中文页面，查看候选、回测曲线和模拟盘。

设计上参考了两个公开项目的规则和数据来源，没有把它们的代码搬进本仓库：

- [shy3130/tick-stock-panel](https://github.com/shy3130/tick-stock-panel)（MIT）：短线策略类型、T+1、费用和涨跌停拒单这些交易约束。
- [simonlin1212/a-stock-data](https://github.com/simonlin1212/a-stock-data)（Apache-2.0）：免费行情该走腾讯、东财容易封 IP、2026 年 9 月通达信公开行情端口不可用。

## 环境

- Python 3.11 或更高。Windows 和常见 Linux 都可以跑。排序模型用 scikit-learn，1.6 及以上在 Windows 的 CPython 3.14 上有 pip 轮子。
- 不需要 QMT、PTrade 或任何券商账号。
- 行情来自腾讯日线；腾讯失败时改用新浪日线。不调用东财。构建这个版本时，东财 `push2his` 返回空连接，所以没有把它当成数据源。
- 报告、缓存、模拟盘账本、`config.json` 和模型文件默认都写在项目根目录下面，不跟着当前工作目录走。从别的文件夹启动也不会把文件写到 C:。需要改位置时用 `--report-dir`、`--cache-dir`、`--paper` 或环境变量 `ASHARE_REPORT_DIR`、`ASHARE_CACHE_DIR`、`ASHARE_LEDGER`、`ASHARE_CONFIG`、`ASHARE_MODEL`。

## 每天怎么用

收盘并且免费行情已经更新之后（上海时间 15:30 以后；周末和交易所休市日没有新的交易日）：

```bash
python -m ashare daily
```

这一句就是收盘后的全部更新：刷新日线、用新 K 线结算已有的模拟盘委托和持仓、再按 `config.json` 生成下一交易日候选。行情过滤允许开新仓时，新候选才会写入模拟盘。

只做均线回踩、并且不用排序模型时，在项目根目录放一份 `config.json`（可以只写这两项，其余用默认值）：

```json
{
  "strategies": ["ma_pullback"],
  "use_ranker": false
}
```

行情过滤没有单独的开关，每天都开着。排序模型在样本外没有形成优势，所以默认 `use_ranker` 是 `false`：即使 `data/models/ranker.pkl` 还在，也不会拿它排序。不写 `config.json` 时，候选仍是首板次日承接和均线回踩，模型同样关闭。

不想改文件时，可以用命令行盖过配置（只对这一次 `daily` 生效）：

```bash
python -m ashare daily --strategies ma_pullback --no-ranker
```

策略 id：`first_board_follow`（首板次日承接）、`breakout_60`（放量突破 60 日高）、`ma_pullback`（均线回踩）、`macd_golden`（MACD 零下金叉）、`shrink_reversal`（缩量回调再放量）。多个 id 用逗号分开。账本里已经存在的其他策略委托仍会结算，新开仓只来自这次选中的策略。

命令会：

1. 默认扫描沪深主板、创业板、科创板的当前名单，并尽量加入样本期内退市的股票。北交所只有在免费名单返回代码时才加入。只要成交额前 N 只时加 `--universe 50`。
2. 丢掉名称里的 ST 和风险警示、按 5% 封板推断出来的 ST 日期、上市初期样本不够的次新、停牌、收盘涨停、收盘跌停、成交额过低、近 20 日振幅不足 10% 的股票。振幅过滤是为了不把工商银行这类低波动大盘股当成短线标的，不是按行业名称拉黑。
3. 用 `strategies` 里的策略产生候选，写出当日的行情状态（是否允许开新仓、涨停家数、炸板率、连板高度）。`use_ranker` 为 true 且模型文件能加载时，按模型分数留下前几名；模型关闭时名单按规则分，报告里写明模型已关闭。模型开着但文件不存在时，按规则分并说明还没训练。
4. 先结算模拟盘里已有的委托和持仓，再决定要不要下新的模拟盘委托。只有行情过滤允许开新仓时才写入新委托，账本是 `data/paper/ledger.json`。过滤不过的日子仍然写出候选，但不会下新委托。`--no-paper` 只出报告，既不结算也不写新委托。

不想记命令时，在仓库根目录打开看盘页：

```bash
python -m ashare dashboard
```

Windows 和 Linux 都是这一句。页面默认无头启动，不会停在 Streamlit 第一次运行时的邮箱提示上。浏览器地址是 `http://127.0.0.1:8501`；如果没有自动弹出，就自己在地址栏输入。端口被占用时加 `--port 8502`。

页面有三块：

- **今日候选：** 最近一份收盘名单，含买入区间、止盈、止损、最长持有天数、建议股数、规则分和模型分数。页首是当天的行情过滤和涨停情绪。模型关闭时这里写「排序模型已关闭」。右上角「运行收盘更新」等同于 `python -m ashare daily`，读的是同一份 `config.json`，也会先结算再出名单。行情过滤不过时不写新的模拟盘委托。
- **回测：** 全样本和走步样本外分成上下两块，各有指标表和可缩放的权益曲线。没有 `reports/backtest_latest.json` 时这块是空的，先运行一次 `python -m ashare backtest`。如果跑过下面的对照实验，页面下方还会多一张行情过滤和模型排序的表。
- **模拟盘：** 现金、持仓、每笔持仓的卖出价和持有天数、待成交委托、成交记录、盈亏曲线。还没结算过就显示空状态，不会编造成交。

`python -m ashare daily` 已经用新日线撮合过已有委托。只结算、不再生成名单时：

```bash
python -m ashare paper settle
python -m ashare paper status
```

开盘价涨停、开盘价高出买入区间、开盘价低于买入区间，委托会被拒绝并记原因。买入当天不能卖。跌停封死的卖出会继续留到后面的交易日。

回测（需要联网，第一次会下载日线并缓存在 `data/cache`，该目录不要提交）：

```bash
python -m ashare backtest
```

第一次会下载几千只日线，缓存在 `data/cache`，中断后重跑会接着下。只要以前那 50 只高成交额样本时：

```bash
python -m ashare backtest --universe 50
```

报告在 `reports/backtest_起始日_结束日.md`，权益曲线是同目录的 PNG。

常用参数：

| 命令 | 作用 |
| --- | --- |
| `--universe 40` | 改用成交额前 40 只，而不是全市场 |
| `--top 8` | 当日报告最多几只 |
| `--start 2024-01-01` | 回测开始日 |
| `--no-paper` | 当日只出报告，不结算也不写入模拟盘 |
| `--strategies ma_pullback` | 这一次用哪些策略，盖过 `config.json` |
| `--ranker` / `--no-ranker` | 这一次是否用排序模型，盖过 `config.json` |
| `--config config.json` | 指定配置，省略时读项目根目录的 `config.json` |

行情过滤和排序模型（全市场，会用已有缓存，第一次仍然要几分钟到更久）：

```bash
python -m ashare research
python -m ashare train
```

`research` 只跑一次对照：规则打分、加上行情过滤、再加上模型排序。超参只在 2025-04-25 之前的数据里选，样本外区间 2025-04-25 至 2026-06-23 不参与挑选。报告写到 `reports/regime_ml_*.md` 和 `reports/regime_ml_latest.json`，不覆盖原来的五策略 `backtest_latest.json`。冻结下来的模型在 `data/models/ranker.pkl`。

`train` 用同一组已经选定的超参，把模型重训到最新一根已经走完的交易，供之后的 `daily` 使用。它会换掉 `ranker.pkl`。想和研究报告里的样本外模型保持一致时，不要在看完样本外之后再跑 `train`。

## 怎么读报告

当日候选表里的每一列：

- **策略 / 理由：** 为什么这只股票在收盘时被选中。
- **模型分数：** 排序模型估计的扣费后收益。没有模型时这一列是空的，名单按规则分排列。
- **买入下限、买入上限：** 下一交易日开盘价必须落在这个区间里才会成交。高于上限视为追高，低于下限视为跳空太弱。
- **止盈、止损：** 按买入区间的中点估算，方便事先看风险。模拟盘一旦成交，会改成按真实成交价计算。
- **最长持有：** 从买入当天算起的交易日。到了这个天数，若没有触发止盈止损，就在收盘尝试卖出。持有 1 天表示下一个交易日就必须处理，这也是 T+1 下最短的持有。
- **建议股数 / 预估金额：** 按 2 万元和上面的仓位上限，向下取整到手。科创板最小 200 股。算出来是 0 的股票不会出现在表里。

回测报告分两块，不要混着看：

- **全样本（默认参数）** 是同一套参数跑完整段历史。参数是对着这段行情定的，数字通常偏乐观。
- **走步样本外** 才是更值得看的结果。每一段测试之前，只用更早的训练窗口在很小的参数格里挑一组，然后冻结，只交易后面那段没参与挑选的行情。样本外亏损或明显差于全样本，就说明这条策略还不能当交易依据。

权益曲线的虚线是初始 2 万元。期末权益已经扣过佣金、印花税、过户费和滑点，持仓按收盘价减去预估卖出成本计价，所以刚买进的当天权益通常会低于本金。

## 五条策略

信号都在收盘时计算，委托是下一交易日的开盘价。收盘已经涨停的股票直接排除，因为收盘阶段买不进去。

| 策略 | 在找什么 | 默认止盈 / 止损 / 最长持有 |
| --- | --- | --- |
| 首板次日承接 | 昨天是第一次涨停，今天收阳而且没有再次封死涨停，量能也没有极端放大 | 6% / 4% / 3 天 |
| 放量突破 60 日高 | 除权连续价收盘突破前 60 个交易日最高价，放量，收盘靠近最高价 | 10% / 6% / 8 天 |
| 均线回踩 | MA5 > MA20 > MA60 且均线向上，当天回踩 MA20 后收阳站回 | 8% / 4% / 8 天 |
| MACD 零下金叉 | DIF 在零轴下方上穿 DEA，收盘仍在 MA20 之上 | 8% / 5% / 8 天 |
| 缩量回调再放量 | 上升趋势里连续三日缩量下跌，今天放量收阳 | 6% / 4% / 5 天 |

除权连续价只用已经发生的除权信息，后面的分红不会改写更早的信号。真正下单和判断涨跌停用的是不复权成交价。

## 回测里的 A 股规则

- **T+1：** 买入当日的持仓不能卖，最早下一个交易日。
- **涨停：** 开盘价达到涨停价，买单作废。主板 ±10%，创业板和科创板 ±20%，北交所 ±30%。价格按分四舍五入。Baostock 当天 `isST=1` 的主板股票按 ±5%。创业板、科创板、北交所即使当天是 ST，仍用 20% 或 30%。
- **跌停：** 全天最高价仍不超过跌停价时，卖单作废，持仓留到后面。低开跌停但收盘打开时，按跌停价上方 1 分钱估算成交，这是偏保守的日线近似。
- **同一根 K 线又碰到止损又碰到止盈：** 算止损。
- **费用：** 佣金默认万 2.5，买卖都收，不足 5 元按 5 元。印花税只在卖出时收取，2023-08-28 之前按 0.1%，之后按 0.05%。过户费买卖都收，按成交额的 0.001%。
- **滑点：** 默认 0.1%，买入更贵，卖出更便宜。
- **整手：** 主板、创业板、北交所 100 股。科创板买入按 200 股递增。
- **仓位：** 单票预算是“净值的四分之一”和“净值的 35%”里更小的那个，并且不能超过现金。

日线看不到集合竞价队列，也看不到“开板又封死”。真实成交通常比这里更难，尤其是强势股。

默认回测用全市场目录，不再只拿当天成交额最高的 50 只。退市股票能不能进来，取决于免费源有没有代码和日线，报告里会写清下载了多少、缺了多少。

ST 和停牌按 Baostock `query_history_k_data_plus` 的 `isST`、`tradestatus` 逐日判断，缓存在 `data/cache/st/{代码}.parquet`（没有 pyarrow 时是同名 JSON）。已经覆盖到最近一个交易日的文件不再请求；缺的只补尾部。某一天是 ST 才从那天的股票池拿掉，不再因为今天的名称里有 ST 就把整段历史丢掉。`tradestatus=0` 的日子不能买卖。Baostock 登录失败或单只查询失败时记警告，已有缓存照常使用；完全没有文件的股票不会按今天的名称整段排除。五策略 `backtest` 和 `daily` / `research` 走的是同一套逐日标记。

## 行情过滤和排序

全市场回测里，五条策略在完整样本上都是亏的。这一步只留下当时样本外略好的两条：首板次日承接、均线回踩。它们仍然只负责产生候选。

行情过滤是事先写死的，没有拿样本外去调：当天至少有 200 只股票能算出 MA20，其中收盘在 MA20 之上的比例不低于 40%，并且由当天有成交的股票做出来的等权指数不低于它自己的 20 日均线。三条里有一条不满足，就不新开仓，已经持有的仍按原规则卖出。比例、均线窗口和最少股票数可以在配置里改，对照实验用的是上面这组默认值。

涨停情绪也从已经缓存的日线里算，不访问额外网页：涨停家数、炸板（最高价碰到涨停、收盘没封住）比例、最高连板、昨日涨停股票今天的平均涨跌。涨跌停宽度按板块：主板 10%，创业板和科创板 20%，北交所 30%，主板里封在 5% 的另外记成 ST 宽度的涨停。

排序模型是 scikit-learn 的梯度提升树。标签是这笔信号如果单独成交，按该策略的止盈、止损和最长持有天数卖出之后、扣掉佣金、印花税、过户费和滑点的收益率。开盘涨停买不进、停牌、不够一手、或者到行情结束还没卖出的，没有标签，不当成 0。训练一行数据时，信号日和卖出日都必须早于截止日。样本外之前用扩展窗口重训，2025-04-25 之后沿用在这天之前冻结的模型。每天先按规则分留下一个候选池（默认 80 只），再用模型分只买分数最高的几只。账户仍然最多 4 只。

这个对照的数字以 `reports/regime_ml_*.md` 为准。样本外交易笔数少，或者收益为正但 t 统计量绝对值不到 2，都不能当成可以模拟盘的优势。

| 股票池快照 | 新浪行情中心 `hs_a`（以及能返回数据的北交所节点） | 该页失败就停止翻页，并用已经拿到的名单 |
| 上市日、退市日 | Baostock `query_stock_basic` | 登录失败时只保留新浪当前上市的股票，报告里会说明退市名单缺失 |

每次请求之间有间隔，多只股票并行但共用这一个间隔。结果缓存在 `data/cache`。一只股票的缓存可以复用，当且仅当里面已经有最近一个已经结束的交易日：上海时间 15:30 之后，当天若是交易日，这一天就是该交易日；15:30 之前、周末，以及交易所休市日，则往前找到上一个交易日。休市表写在 `ashare/market_calendar.py`，覆盖 2024–2026 年（下一年交易所公布后需要补上）。周末从来不是交易日。

缺的只是最近大约 40 个自然日时，只向腾讯（失败则新浪）请求这一小段并合并进缓存，不把整段历史重新下载一遍。合并对不上、出现空洞时，才退回整段下载。全市场更新时，已经覆盖最近交易日的股票只读取缓存里的最后日期，不把全部 K 线同时放进内存；需要补的股票写完盘就丢掉下载结果，再逐只整理成回测用的序列。退市或长期停牌的股票，最后一根 K 线比最近交易日早 20 天以上，并且缓存是近 7 天写的，就不再重复请求。行情源在收盘后晚几分钟还没给出当天 K 线时，这次不会把旧缓存当成最新，下次运行会再试。

通达信公开服务器在 2026 年 9 月的公开记录里已经取不到行情。日线主源仍然是腾讯和新浪，不依赖通达信。可选包 `eltdx` 走通达信行情协议，只在收盘后给当天涨停和接近涨停的股票补 1 分钟线，用来算首封时间、炸板次数、是否回封，以及 09:25 集合竞价的价格和成交量（手）。结果在 `data/cache/intraday/{日期}.parquet`。这些字段只出现在当日候选和看盘页上，不改回测里的规则分，因为分钟线能回溯多远必须在运行的那台机器上测：程序会用 `sh600000` 往前试历史分时，把最早拿到的日期写到 `data/cache/intraday/depth.json`。云主机上的探测结果不能当成你电脑上的深度。`eltdx` 的许可是研究用途，个人使用可以。

涨停池、炸板池、跌停池在 `python -m ashare daily` 写出候选之后再拉。优先用同花顺官方接口 `https://fuyao.aicubes.cn`（涨停 / 跌停 / 炸板三个池，HTTP 429 或响应 `code=4001` 会退避重试；成功码只认 `code=0`）。没有密钥或接口失败时改用 akshare 的 `stock_zt_pool_em`、`stock_zt_pool_zbgc_em`、`stock_zt_pool_dtgc_em`，龙虎榜用 `stock_lhb_detail_em`。东财以前在这台网络上返回过空表，空表或异常都只记警告，不会让收盘更新中断。每天一份快照在 `data/cache/pools/{日期}.parquet`，来源写在里面。看盘页读 `reports/pool_latest.json`，显示涨停家数、炸板率、最高连板，以及能拿到的封板时间和原因。

东财接口容易封 IP。日线不访问东财。涨停池的东财路径只是同花顺失败后的备用。

## 模拟盘和以后的实盘

模拟盘账本是 `data/paper/ledger.json`。成交记录只追加含义上的状态变更（委托从 pending 变成 filled 或 rejected），现金和持仓随结算更新。这是研究账，不是券商对账单。

代码里的下单接口在 `ashare/broker/base.py`：

- `PaperBroker`：v1 唯一会运行的实现。
- `MiniQMTBroker`：构造时直接报错，避免误连实盘。

以后要做自动下单，大致是这些步骤，而不是改策略公式：

1. 在券商开立普通 A 股账户。程序化交易一般还要单独申请量化或程序化权限。各家券商对资产、交易经验、知识测试和风险揭示的要求不一样，没有这个权限就不能用 miniQMT 下单。
2. 在 **Windows** 上安装券商提供的 miniQMT 客户端。xtquant 随客户端提供，通常不能在 Linux 上直接交易。
3. 新增一个 `Broker` 子类，把 `place_orders` 转成 `xtquant` 的下单调用，把柜台回报转回现在的持仓和现金结构。策略、费用和 T+1 规则保持不动。
4. 先用模拟盘和券商的仿真环境对照一段时间，确认股数、价格类型和废单处理一致，再考虑极小资金。本仓库的 v1 不包含这一步。

## 风险

- 没有承诺收益，也没有“稳赚”参数。样本外结果差，就应该继续空仓或改研究，而不是加大仓位。
- 2 万元很怕最低 5 元佣金。买卖一次，光佣金就要 10 元，再加印花税和滑点，小波动会被费用吃掉。
- 短线策略在一段时间有效、在另一段失效是常态。
- 免费行情会延迟、缺失、在除权日口径不一致。用它做研究可以，用它自动下真金白银不行。
- 作者和本工具都不对交易损失负责。下单之前要自己核对价格、公告和仓位。
